# Toy Racers architecture

Toy Racers has two implementations sharing one behavioral contract:

```text
Kotlin/libGDX reference implementation  <-->  shared compatibility contracts
                                              <-->  Dart/Flutter/Flame migration
```

The Kotlin/libGDX code in the core and platform modules is the reference
implementation and behavioral oracle. The compatibility inventory has two
stores: 50 legacy scenarios and goldens in
`core/src/test/resources/compat/`, plus 63 file-based fixtures in the
repository-level `compatibility/` area. `compatibility/` is the canonical
per-file contract area; the shared comparator contract is defined there, while
the comparator implementation and CLI live in
`core/src/main/kotlin/com/example/toyracers/compat/`. The Dart migration is an
independent Flutter project in `dart/`; it consumes those shared contracts and
is compared to Kotlin rather than replacing or depending on Kotlin at runtime.

Both implementations use the canonical repository-level `assets/` source.
The Dart asset mirror at `dart/assets/` is generated by
`tools/flutter_asset_pipeline.py` for Flutter packaging. It must stay
synchronized, but it is not the canonical source.

Inside Dart, pure deterministic simulation is kept in `dart/lib/simulation/`.
Flutter, Flame, device input, rendering, camera, and audio remain in Dart's
presentation layers. The headless Dart behavior runner emits the shared trace
format without starting Flutter or Flame, allowing Kotlin-to-Dart differential
testing to remain platform-independent.

The migration has passing recorded compatibility evidence, but it is not yet a
claim of complete release readiness: representative-device rendering
performance, audible output, and several platform-native runtime checks remain
open. See the Dart [migration report](dart/docs/MIGRATION_REPORT.md),
[platform support matrix](dart/docs/PLATFORM_SUPPORT.md), and
[Dart architecture](dart/docs/ARCHITECTURE.md) for the current evidence and
limitations.
