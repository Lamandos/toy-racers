# План покрытия unit-тестами

## Цель и измерение

- Поддерживать не менее 75% покрытия строк переносимой игровой логики в модуле `core`.
- Измерять покрытие задачей `./gradlew core:jacocoTestReport`.
- Проверять порог задачей `./gradlew core:jacocoTestCoverageVerification`.
- HTML-отчёт создаётся в `core/build/reports/jacoco/test/html/index.html`.

Базовый отчёт от 2026-08-01: 88,51% строк и 80,94% инструкций. Таким образом, текущий набор
содержательных unit-тестов уже превышает обязательный порог; verification task не позволит
последующим изменениям опустить покрытие строк ниже 75%.

В область unit-покрытия входят пакеты `ai`, `camera`, `car`, `collision`, `race`, `surface`,
`track`, а также чистые модели `PlayerInput` и `PlayerControlConfig`. Это детерминированная
simulation/domain-часть без зависимости от графического контекста.

Экраны, UI stages, рендереры, аудио и загрузка ресурсов LibGDX не входят в порог unit-покрытия:
они требуют графического или платформенного окружения и должны проверяться интеграционными и
smoke-тестами. Такое разделение не позволяет инфраструктурному коду скрывать пробелы в тестах
игровых правил.

## Приоритеты тестирования

1. Физика автомобиля, столкновения и ограничения скорости поверхности.
2. Правила гонки: старт, пауза, контрольные точки, круги, финиш и позиции.
3. Детерминированные решения AI и обработка управления игрока.
4. Геометрия трассы, загрузка collision data и конфигурационные ограничения.
5. Камера и чистые вычисления представления, не требующие OpenGL.

Для новой или изменённой игровой логики тест должен проверять наблюдаемое поведение и граничные
условия. Тесты должны оставаться детерминированными; достижение процента без проверки полезного
сценария не является целью.

## Автоматическая проверка

Репозиторный hook `.githooks/pre-commit` перед каждым коммитом запускает все unit-тесты и проверку
порога покрытия. Для нового клона нужно один раз выполнить:

```sh
git config core.hooksPath .githooks
```

Если тест или порог покрытия не проходит, коммит отменяется.
